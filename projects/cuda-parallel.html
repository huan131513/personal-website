CUDA 高效能平行運算

2D 卷積運算是影像處理與深度學習的核心操作之一，但單執行緒實作在大尺寸影像上會非常慢。 這個專案用 OpenMP 做多核心 CPU 平行化、CUDA 做 GPU 平行化， 並針對硬體記憶體階層設計存取策略，實測比較不同平行化策略對運算時間的影響。

高效能運算 / GPU 課程專案 2024

要解決的問題

2D 卷積（convolution）是影像濾波、特徵萃取、CNN 前向傳播的基礎運算： 每個輸出像素都要對輸入影像的一小塊鄰域跟卷積核做內積。 單執行緒實作的時間複雜度隨影像尺寸與卷積核大小快速增長， 在大尺寸輸入上會變成明顯的效能瓶頸——但這個運算本質上是高度平行的： 每個輸出像素的計算彼此獨立，非常適合拿來練平行運算的硬功夫。

兩種平行化策略

OpenMP（CPU 多核心）：用 #pragma omp parallel for 把輸出影像的列或區塊切給多個執行緒同時處理，重點在避免 false sharing、 平衡每個執行緒的工作量。

CUDA（GPU）：把輸出影像切成多個 Block， 每個 Block 再切成多個 Thread，讓數千個執行緒同時計算不同的輸出像素。 重點不在「切得多細」，而在記憶體存取模式—— 相鄰輸出像素會重複讀取到相同的輸入鄰域，如果每個 thread 都各自從 global memory 重新讀取，頻寬會成為瓶頸；所以把該 block 需要的輸入資料 先搬進 shared memory，讓同一 block 內的 thread 共用， 大幅減少對 global memory 的重複存取。

記憶體存取最佳化

GPU 的記憶體階層由快到慢大致是 Register → Shared Memory → Global Memory， 容量也依序變大。最佳化的核心思路是：盡量把會被重複讀取的資料留在離運算單元最近的層級。 對 2D 卷積來說，具體做法包括：

  • Tiling：每個 block 先把自己負責的輸出區域對應的輸入鄰域（含 halo 邊界）整塊搬進 shared memory，再讓 block 內所有 thread 讀取這份共用資料，而不是各自打到 global memory。
  • Coalesced access：設計 thread 對 global memory 的讀取順序，讓同一個 warp 內的 threads 存取連續的記憶體位址，善用 GPU 的合併存取機制。
  • Block/thread 維度調整：依卷積核大小與 GPU 架構的 SM 資源，調整 block 尺寸，在平行度與 shared memory 用量之間找到平衡點。

效能比較

比較單執行緒、OpenMP 多核心、以及 CUDA（含／不含 shared memory 最佳化） 在同樣輸入尺寸與卷積核下的運算時間，觀察平行化與記憶體策略各自帶來的加速幅度。

學到的事：GPU 平行運算的瓶頸經常不在「算得夠不夠快」，而在 記憶體頻寬——同樣的運算邏輯，把資料搬到 shared memory 減少重複的 global memory 存取，往往比單純增加 thread 數量帶來更大的加速。 理解硬體的記憶體階層，是寫出真正快的 CUDA 程式的關鍵。
